## 一、NRF24L01 工作配置（两端口径必须一致）

小车端与遥控器端在 `NRF24L01_Init()` 里写入相同的寄存器配置，任何一处不一致都会收不到包。寄存器值（`NRF24L01.c` 第 602~613 行）：

| 寄存器 | 写入值 | 含义 |
|---|---|---|
| EN_AA | 0x3F | 使能自动应答（接收通道 0~5 全开） |
| EN_RXADDR | 0x01 | 只开启接收通道 0 |
| SETUP_AW | 0x03 | 地址宽度 5 字节 |
| SETUP_RETR | 0x03 | 自动重传：间隔 250us，重传 3 次 |
| RF_CH | 0x02 | 射频信道 2 → 频率 2402MHz |
| RF_SETUP | 0x0E | 速率 2Mbps，发射功率 0dBm |
| RX_PW_P0 | 32 | 通道 0 接收数据宽度 32 字节（定长包） |
| RX_ADDR_P0 | 11 22 33 44 55 | 通道 0 地址（双端一致） |

**要点**：
- 收发共用同一个 5 字节地址 `11 22 33 44 55`；
- 32 字节**定长**包——不管有没有数据，发送/接收缓冲都是 32 字节，双方约定只用前若干字节；
- 硬件自动应答 + 重传 3 次：发送失败不用程序管，NRF 芯片自己重发，发成功与否由 `STATUS` 寄存器反映；
- 双端 SPI 引脚不同（小车 PA8/PA15/PB3/PB4/PB5，遥控器 PB11~PB15），但**配置值必须相同**。

## 二、遥控器 → 小车：控制包（前 6 字节有效）

遥控器每 100ms 组一次包（`main.c` 的 Flag 节拍）：

| 字节 | 变量 | 取值范围 | 含义 |
|---|---|---|---|
| [0] | ID = Mode | 0x00 / 0x01 | 0x00 不需要回传；0x01 需要小车回传数据 |
| [1] | LH | -100~100 (int8) | 左摇杆横向（保留，小车端未使用） |
| [2] | LV | -100~100 (int8) | 左摇杆纵向 → 小车速度目标 |
| [3] | RH | -100~100 (int8) | 右摇杆横向 → 小车转向目标 |
| [4] | RV | -100~100 (int8) | 右摇杆纵向（保留） |
| [5] | KEY | 0~12 | 按键键码（0=无键，1/2/3 对应小车 K1/K2/K3） |

小车端解析（`main.c` 主循环 RF 分支）：

```c
SpeedPID.Target = LV / 25.0f;        // 摇杆 100 → 速度目标 4.0
TurnPID.Target  = RH / 25.0f;        // 摇杆 100 → 转向目标 4.0
if (KEY == 1) Key_Flag[KEY_1] |= KEY_SINGLE;   // 模拟小车 K1（启动/停止）
```

**按键为什么要"发送成功后才清零"？** 遥控器 `main.c` 中 `SendFlag==1` 才把 KEY 清 0：如果这包没发出去，KEY 保留到下一包继续发，保证按键指令不丢。

## 三、小车 → 遥控器：回传包（ID=0x02，前 16 字节有效）

遥控器发来 ID=0x01（要回传）时，小车收到控制包后立即回一包：

| 字节 | 内容 | 类型 | 说明 |
|---|---|---|---|
| [0] | ID | uint8 | 固定 0x02 |
| [1] | PWML | int8 | 左轮 PWM（-100~100） |
| [2] | PWMR | int8 | 右轮 PWM |
| [3] | （未用） | — | 保留 |
| [4..7] | Angle | float 小端 | 车身倾角（互补滤波后） |
| [8..11] | SpeedLeft | float 小端 | 左轮速度（圈/秒） |
| [12..15] | SpeedRight | float 小端 | 右轮速度 |

代码写法（两端一致）：`*(float*)&NRF24L01_TxPacket[4] = Angle;`——**直接把 float 的 4 字节内存原样搬进包**，小端序，接收端同样用 `*(float*)&RxPacket[4]` 读回。这是嵌入式里最常用的打包方式，效率最高，但要求两端字节序一致（同为小端即一致）。

遥控器端显示（Mode=1 时）：`Angle / PWM / Spd` 三行。

## 四、蓝牙协议（手机上位机）

蓝牙模块接小车 USART2（PA2/PA3，9600 8N1），文本帧格式，每帧以换行结束：

| 帧格式 | 示例 | 效果 |
|---|---|---|
| `[joystick,LH,LV,RH,RV]` | `[joystick,0,60,0,0]` | 摇杆：LV=60 前进 |
| `[key,1,up]` | — | 等效按下小车 K1（启动/停止） |
| `[key,2,up]` | — | 等效按下小车 K2（前进） |
| `[key,3,up]` | — | 等效按下小车 K3（后退） |

解析规则（`main.c` 蓝牙分支）：

```c
// 摇杆帧：LV 归一化到 ±100，再乘速度档位
SpeedPID.Target = LV / 100.0 * SpeedLevel;   // SpeedLevel 默认 4
TurnPID.Target  = RH / 100.0 * SpeedLevel;
// 按键帧：仅 [key,N,up] 有效（按下沿触发）
```

**与 RF 控制的区别**：RF 的 LV 用 `/25`（摇杆 100 → 速度 4.0），蓝牙的 LV 用 `/100*SpeedLevel`（SpeedLevel=4 时也是 100 → 4.0），两者满杆速度一致，但蓝牙多了速度档位可调（SpeedLevel 存在 Flash 里）。

**前提条件**：蓝牙指令只在 `ControlMode == CONTROL_MODE_BT` 时生效，需要先在车上 K4 长按切换到 BT 模式。

## 五、失联保护（500ms 软件看门狗）

这是安全兜底，逻辑在 `main.c` 1ms 中断里：

```
条件：ControlMode 是 RF 或 BT，且 RunFlag=1（车在运行）
  每 1ms：RemoteWatchdog++
  RemoteWatchdog == 500（即 500ms）→ RemoteTimeoutFlag = 1（只触发一次）
  主循环看到 RemoteTimeoutFlag → PID_Init(速度环/转向环)，目标清零，车原地驻停

任一模式收到有效控制包 → RemoteWatchdog = 0（重新计时）
K4 长按切模式 → RemoteWatchdog = 0（重新计时）
本机按键模式（KEY）→ 看门狗不工作
```

**为什么不直接清零 RunFlag？** 失联只清"行驶/转向目标"，保留"直立"——车停住但不倒，等人回来遥控。手机端蓝牙发指令时，建议间隔 50~100ms，不要低于看门狗节奏，也不要一停一停地发（容易触发超时）。

## 六、信号强度指示（SuccessRatio）

遥控器 OLED 第一行 `Sig:xx` 显示信号强度，算法是**最近 10 次发送的成功次数**（`CalculateSuccessRatio`）：

```
SendFlagArray[p] = SendFlag;   // 循环覆盖存最近 10 次
成功次数 = 数组里等于 1 的个数   // 0~10
```

- `Sig:10` = 近 10 包全成功，信号好；
- `Sig:5` 以下 = 明显丢包，检查天线、距离、供电；
- 这个值只反映**发送**成功率（遥控→小车），配合回传数据（Angle 是否刷新）可判断双向链路。

## 七、双端联调自测清单

1. 遥控器 OLED 显示 `Sig:10`（或 9~10）；
2. 车上 K4 长按切到 RF 模式（OLED 第 5 行显示 `Mode:RF`）；
3. 打左摇杆前进，车应起步；松杆后约 500ms 内驻停；
4. 遥控器 K9 切到 Mode=1，OLED 应显示小车回传的 Angle/PWM/Spd，且数值随车晃动变化；
5. 手机蓝牙连上模块，车切到 BT 模式，发 `[joystick,0,60,0,0]` 应前进。
