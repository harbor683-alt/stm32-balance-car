## 一、双端系统总体架构

这套项目是**两块独立的 STM32F103C8T6 板子 + 一条 2.4G 无线链路**组成的闭环：

- **小车端**负责"平衡 + 执行"：读姿态、测轮速、跑三环 PID、驱动电机，同时监听三类输入（本机按键 / NRF 手柄 / 手机蓝牙）。
- **遥控器端**负责"输入 + 反馈"：读双摇杆和 12 个按键，每 100ms 打包发给小车，并可选接收小车回传的姿态/速度数据在 OLED 上显示。

```mermaid
flowchart LR
    subgraph REMOTE["遥控器端（02_遥控器烧录程序）"]
        A1["双摇杆 ×2（ADC 采样）"] --> A2["DataProcess 归一化到 -100~100"]
        A3["K1~K12 按键"] --> A2
        A2 --> A4["打包 6 字节数据包"]
        A4 --> A5["NRF24L01 发送（100ms 一次）"]
        A5 --> A6["OLED：信号强度 / 回传数据"]
    end

    subgraph CAR["小车端（01_小车烧录程序）"]
        B1["NRF24L01 接收 + 解析"] --> B2["速度目标 / 转向目标"]
        B3["手机蓝牙（USART2 9600）"] --> B2
        B4["本机按键 K1~K4"] --> B2
        B2 --> B5["三环串级 PID"]
        B5 --> B6["TB6612 → 左右电机"]
        B7["MPU6050 姿态 / 编码器测速"] --> B5
        B1 --> B8["ID=0x01 时回传数据包"]
        B8 --> A6
    end

    A5 -- "2.4G · 2Mbps · 32字节定长" --> B1
    B1 -- "ACK 自动应答 + 重传3次" --> A5
    B3 -- "蓝牙透传文本帧" --> CAR
```

一句话记住分工：**遥控器只发指令，小车只管平衡；小车偶尔回传"我现在多快、多斜"，遥控器负责显示。**

## 二、小车端整体代码框架

小车端的主程序在 `01_小车烧录程序/User/main.c`，**`main()` 只做初始化和显示，真正干活的循环有两层**：

1. `while(1)` 主循环——处理按键、遥控包、显示，节奏"随便"（不精确，但都很快）；
2. `TIM1_UP_IRQHandler` 1ms 定时中断——**所有需要精确节拍的事（姿态、测速、PID）都在这**。

```mermaid
flowchart TD
    START(["上电复位"]) --> INIT["初始化全部外设<br/>OLED/LED/Key/Motor/Encoder<br/>MPU6050/BlueSerial/NRF/Serial/Timer"]
    INIT --> BOOT["显示开机界面<br/>等待 K4 确认"]
    BOOT --> STORE{"Store_Init() 检查<br/>Flash 里有没有参数?"}
    STORE -- "首次烧录，无参数" --> SAVE["默认参数写入 Flash<br/>提示：请注意执行校准"]
    SAVE --> WAITK4["等待 K4 确认"]
    WAITK4 --> LOAD["LoadParam() 加载参数"]
    STORE -- "已有参数" --> LOAD
    LOAD --> LOOP

    subgraph LOOP["while(1) 主循环：无严格节拍"]
        K1["K1 启动/停止<br/>（启动时三环 PID_Init，角度取当前滤波值）"]
        K2["K2 前进 / K3 后退<br/>目标速度 ±2.0"]
        K4["K4 短按=驻停（保持直立）<br/>K4 长按=切换 KEY→RF→BT"]
        TIMEOUT["失联超时处理<br/>RemoteTimeoutFlag 置位 → 停车"]
        RF["RF 模式：NRF 收包<br/>LV→速度目标 / RH→转向目标<br/>键码 1/2/3 模拟 K1/K2/K3<br/>ID=0x01 时组回传包 0x02 发送"]
        BT["BT 模式：蓝牙收包<br/>[joystick,...] → 速度/转向<br/>[key,...] → 模拟按键"]
        OLED["OLED 刷新 6 行运行数据"]
        K1 --> K2 --> K4 --> TIMEOUT --> RF --> BT --> OLED --> K1
    end

    LOOP --> INT["TIM1 更新中断（每 1ms）"]

    subgraph INT["TIM1_UP_IRQHandler：1ms 心跳，所有实时任务按节拍分频"]
        T1["Key_Tick() 非阻塞按键扫描"]
        T2["遥控看门狗：RF/BT 模式下<br/>500ms 无有效包 → 置 RemoteTimeoutFlag"]
        T3{"DebugFlag 为 1？"}
        T3 -- "是" --> T4["直接返回<br/>（调试模式不跑 PID）"]
        T3 -- "否" --> S10{"SensorCount0 ≥ 10ms？"}
        S10 -- "是" --> P10["姿态解算<br/>MPU6050 读原始数据<br/>atan2 加速度角度 + 陀螺积分<br/>低通 + 互补滤波<br/>|Angle|>50° 判定倒地停车"]
        S50{"SensorCount1 ≥ 50ms？"} --> P50["编码器测速<br/>Speed=Encoder_Get/408/0.05<br/>计算 AveSpeed / DifSpeed"]
        S10 -- "否" --> S50
        P10 --> RUN{"RunFlag 为 1？"}
        P50 --> RUN
        RUN -- "是" --> R10{"RunCount0 ≥ 10ms？"}
        R10 -- "是" --> C10["角度环 PID<br/>AvePWM = -AnglePID.Out<br/>PWML = Ave+Dif / PWMR = Ave-Dif<br/>限幅 ±100 → Motor_SetPWM"]
        R50{"RunCount1 ≥ 50ms？"} --> C50["速度环 PID → 角度环目标<br/>转向环 PID → 差分 PWM"]
        R10 -- "否" --> R50
        C10 --> T1
        C50 --> T1
        RUN -- "否" --> STOP["电机 PWM 清零"]
        STOP --> T1
        T4 --> T1
    end
```

### 小车端 1ms 中断时间片调度表

`SensorCount0 / SensorCount1 / RunCount0 / RunCount1` 四个计数器在中断里各自分频，互不阻塞，全部"到点就做"：

| 周期 | 任务 | 用的计数器 | 涉及模块 |
|---|---|---|---|
| 1ms | 非阻塞按键扫描 | 每次进入都调 | `Key.c` |
| 1ms | 遥控看门狗计时（RF/BT 模式） | 每次进入都调 | `main.c` 全局变量 |
| 10ms | 读 MPU6050 → 姿态解算 → 互补滤波 → 倒地检测 | `SensorCount0` | `MPU6050.c / MyI2C.c` |
| 10ms | 角度环 PID → 合成左右 PWM → 限幅 → 输出电机 | `RunCount0` | `PID.c / Motor.c` |
| 50ms | 编码器测速 → 均速 / 差速 | `SensorCount1` | `Encoder.c` |
| 50ms | 速度环 PID（输出=角度环目标）+ 转向环 PID（输出=差分 PWM） | `RunCount1` | `PID.c` |

注意执行顺序：**同一轮中断里，先算 10ms 的姿态和角度环（用上一轮 50ms 更新的目标），后算 50ms 的测速和速度/转向环（为下一轮准备新目标）**。速度环每 50ms 更新一次角度目标，角度环每 10ms 追一次目标。

## 三、遥控器端整体代码框架

遥控器端主程序在 `02_遥控器烧录程序/User/main.c`，结构比小车端简单得多：主循环里采样、处理、发送、显示，定时中断只负责两件事——按键扫描和 100ms 置发送标志。

```mermaid
flowchart TD
    START(["上电复位"]) --> INIT["初始化 OLED / NRF24L01<br/>Key / AD / Timer（1ms）"]
    INIT --> LOOP

    subgraph LOOP["while(1) 主循环"]
        KEY["Key_GetNum() 获取键码<br/>K9 按下 → 切换 Mode（0=不回传 / 1=回传）"]
        ADC["读 4 路摇杆 ADC<br/>PA0~PA3，0~4095"]
        PROC["DataProcess 归一化<br/>减中值 2048 → 死区 ±100 → ×101/1949 → -100~100"]
        FLAG{"Flag == 1？<br/>（定时中断每 100ms 置 1）"}
        FLAG -- "是" --> SEND["打包 6 字节：ID/LH/LV/RH/RV/KEY<br/>NRF24L01 发送 → SendFlag"]
        SEND --> RATIO["CalculateSuccessRatio<br/>统计最近 10 次发送成功率"]
        RATIO --> CLEAR["发送成功才清 KEY<br/>（保证按键指令不丢）"]
        CLEAR --> OLED
        FLAG -- "否" --> OLED
        OLED["Mode=0：显示摇杆值<br/>Mode=1：收 0x02 回传包<br/>显示 Angle / PWM / Speed"]
        OLED --> KEY
    end

    LOOP --> INT["TIM1 更新中断（每 1ms）"]

    subgraph INT["TIM1_UP_IRQHandler：1ms 心跳"]
        T1["Key_Tick() 非阻塞按键扫描"]
        T2["Count ≥ 100？<br/>是 → Count=0，Flag=1<br/>（通知主循环该发包了）"]
        T1 --> T2
    end
```

### 遥控器端时间片调度表

| 周期 | 任务 | 说明 |
|---|---|---|
| 1ms | 按键扫描 `Key_Tick()` | 与小车端同一套非阻塞驱动 |
| 100ms | `Flag` 置 1 | 主循环看到 Flag 才组包发送 |
| 主循环（≈ms 级） | 采样 4 路 ADC → 归一化 → 发送 → 成功率统计 → 显示 | 无严格节拍 |

**为什么发包要固定在 100ms？** 因为 NRF24L01 是半双工，发送期间不能收；小车回传包也要走同一根天线。100ms 发包 + 自动应答，收发错开，信号才稳定。手机上发蓝牙指令时建议同样用 50~100ms 的间隔。

## 五、模块职责速查

| 模块 | 文件 | 干什么 | 关键函数 |
|---|---|---|---|
| 定时器 | `System/Timer.c` | TIM1 配成 1ms 更新中断，整个工程的"心跳" | `Timer_Init()` |
| 姿态 | `Hardware/MPU6050.c` | 软件 I2C 读加速度/陀螺仪原始数据 | `MPU6050_Init/GetData` |
| 测速 | `Hardware/Encoder.c` | 定时器编码器模式读左右轮转速 | `Encoder_Get(n)` |
| 电机 | `Hardware/PWM.c` + `Motor.c` | TIM2 输出 20kHz PWM；TB6612 方向与占空比 | `Motor_SetPWM(1/2, ±100)` |
| 无线 | `Hardware/NRF24L01.c` | 软件 SPI 驱动 NRF24L01 收发 | `NRF24L01_Receive/Send` |
| 蓝牙 | `Hardware/BlueSerial.c` | USART2 收文本帧并切词 | `BlueSerial_ReceiveFlag/Receive` |
| 按键 | `Hardware/Key.c` | 非阻塞状态机：单击/长按/连发 | `Key_Tick`（中断里）+ `Key_Check`（主循环） |
| 显示 | `Hardware/OLED.c` | SSD1306 显示与绘图 | `OLED_Printf/Update/DrawLine` |
| 存储 | `System/Store.c` | 参数存取 Flash | `Store_Init/SaveParam/LoadParam` |
| PID | `User/PID.c` | 位置式 PID（含积分限幅/微分先行/死区补偿） | `PID_Init/Update` |
| 调试菜单 | `User/DebugMode.c` | 硬件测试/校准菜单（**当前固件未接线**） | `DebugMode()` |

> **一个必须知道的真相**：`DebugMode()` 函数写好了，但 `main.c` 里没有任何调用它的地方——现成固件里**进不去调试菜单、也进不去校准流程**。原因和启用方法见 `04_代码导读.md` 最后一节，这是本工程源码里唯一一处"写了但没接上"的功能。
